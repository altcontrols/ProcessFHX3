Saved selections (rule files)

Optional. Use this when you clean the same kind of export again and again. Instead of ticking the same boxes every time, save the selection as a short rule file, then load and apply it to the next export.

  1. Tick what you want in the main list, then press Rules from current selection.
  2. Save as .prc… to keep it. Next time, Load .prc… and press Apply.

This is the same .prc “procedure” format as ProcessFHX2, so older rule files work here. Ready-made examples (keep EM classes, keep one unit, drop library items) are in the Examples folder next to this page. Rules run top to bottom; Help lists the syntax.

ProcessFHX 3 v1.2 — Help

Workflow

  1. Open a DeltaV export (Open FHX…, Ctrl/⌘ O, or drop the file on the page). Everything starts as kept. In Chrome and Edge the start screen lists your recent files for one-click reopening; the browser may ask once per file whether to allow it, and "Allow on every visit" stops it asking again.
  2. Untick items, use the type list on the left (its checkbox selects or deselects a whole group; Select all / None sit at the top), tick the box at the top of the list to select or deselect everything shown, or filter and use Select shown / Deselect shown. Drag the left pane's edge, or the edge of any column heading, to resize it; double-click to reset.
  3. Use All / Selected / Removed above the list to review exactly what will be saved or left out. Undo / Redo (Ctrl+Z / Ctrl+Y) step back through every selection change, so a stray None or Select all is harmless.
  4. Open Export check to see what the kept items reference but you've excluded. Those must already exist in the target database, or the import will fail.
  5. Save clean FHX. The save dialog lists what's being removed so you can spot accidental drops. After saving, the file is re-read and checked automatically; ✓ Verified appears at the bottom when it holds exactly your selection, unchanged. The Save dialog reopens the last folder you saved to; Choose output folder… in the save dialog sets a fixed one instead (Chrome and Edge). Optionally save the selection (Saved selections → Save as .prc) to repeat the same clean on the next export.

Explorer view

The left pane has two layouts. Types groups items by what they are. Explorer lays them out the way DeltaV Explorer does, rebuilt from the export itself: Library › category folders (classes, composite templates, named sets…), System Configuration › Control Strategies › plant area › process cell › unit › modules, Physical Network › Control Network › controller › assigned modules, plus Recipes and Setup. Click ▸ to expand a folder, click its name to list everything under it, and tick its checkbox to select or deselect all of that. Areas, cells, units and controllers are folders that are also items in the file, so their checkbox covers the item itself as well.

Compare / combine

Compare… opens a second export (B) and pairs its items with this one (A) by type and name. It lists what is only in A, only in B, in both but changed, and in both and identical. user= and time= stamps are ignored, so an item only counts as changed when its content differs. From there you can select any of those groups in the list, or Save combined FHX…: A's current selection, followed by the items only in B, with either A's or B's version of the changed items. Items taken from B bring their embedded composites with them. The combined file is re-read, counted and checked for duplicate names before it is saved. Both files must use the same encoding.

Equipment vs control modules

Module classes and module instances are split into equipment-module (EM) and control-module (CM) groups. A class counts as an EM when DeltaV files it under Equipment Module Classes, or when it uses a command- or state-driven algorithm. An instance takes its kind from its class. Phase classes have their own group.

Embedded composites & hidden definitions

Each one is labelled with the class/module and block that use it, for example EM01-00 › COMMAND_00001, taken from the comment DeltaV writes above it in the export. Filtering by a class name also finds its embedded composites. DeltaV exports a class's or module's private logic (SFCs, embedded composites, action blocks) as separate FUNCTION_BLOCK_DEFINITION NAME="__695C4276_014330EB__" items. ProcessFHX 3 follows the references and keeps exactly the hidden definitions that kept items use, including nested ones. Hidden definitions that belong to dropped items are removed with them. To choose them yourself, tick Choose embedded composites manually at the bottom of Export check: automatic keep/drop turns off, every composite starts out kept (as ProcessFHX2 did), and you can untick individual ones. Export check then lists any composite a kept item still needs. Untick the option to go back to automatic.

SCHEMA and LOCALE are always kept, because DeltaV needs them to import the file.

Saved selections — rule syntax

One rule per line. Lines starting with # are comments.

SELECT_ALL / SELECT_NONEKeep or drop everything.
FIELD = <text>,<True|False>,<Select|Deselect>Exact match. The middle value is case sensitive.
FIELD Contains <text>,…Substring match.
FIELD Matches <regex>,…Regular expression (new in v3).
FIELD is one ofCATEGORY NAME TAG TYPE USER PLANT_AREA CLASS. NAME also matches the tag of items that have no name. CLASS also matches MODULE_CLASS.
REQD_FBSAlso keep the function block definitions and templates that kept items use, recursively (same as ProcessFHX2).
REQD_ALLAlso keep everything kept items reference (classes, named sets, composites, areas…), recursively (new in v3).

Example — keep two EM classes and nothing from the library:

SELECT_NONE
TYPE = <MODULE_CLASS>,<True>,<Select>
NAME Matches <^EM0[13]-00$>,<True>,<Select>
CATEGORY Contains <Control Module Classes>,<True>,<Deselect>
